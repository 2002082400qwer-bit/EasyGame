# 从逐帧图片迁移到实时骨骼（2026-10-16）

游戏入口已经使用实时骨骼。保留旧方案已经实现的输入、物理和35个逻辑状态，运行只加载三视图各16件的48张固定PNG，不再加载旧动作图集、逐帧图片或动作JSON。没有重新生成角色美术。旧素材保留作历史参考。

## 功能承接

| 旧方案功能 | 实时骨骼实现 |
| --- | --- |
| 正、左、背、右四向 | 三套固定绑定，右侧完整镜像左侧关节、枢轴和贴图 |
| 待机、慢走、跑步 | 按连续动作时间插值；沿用已有交替摆臂、抬腿和跑步腾空姿势 |
| 站立起跳、空中动作、落地 | 使用真实跳跃计时收腿，世界升降仅由物理控制；真实接地后屈膝缓冲 |
| 下蹲、蹲行、起身 | 按实际蹲深混合上身，并用腿部逆运动学保持两脚接地 |
| 站冲、冲刺、蹲冲后站立 | 共用0.18秒物理冲刺时间；保存起冲前实际蹲深，半蹲也可连续衔接 |
| 八条90度转向、180度两段转向 | 保留状态机；三张固定视图在中段短交叉过渡，只压窄横向，不压缩身高 |
| 冲刺残影、碰撞框、重置 | 沿用原入口，残影也绘制同一套固定拆件 |
| 操作与物理 | A/D、Ctrl、空格、S、Shift、1/2/3/4、R、F1、Esc保持；移动、重力、冷却和空中一次冲刺规则保持 |

35个逻辑状态为三视图各9类动作/衔接，加8条转向；这些状态现在选择和组合骨骼姿势，不再代表35套图片。程序内保存三视图六基础动作的关节采样，按运行时间连续插值。采样只存角度、位移和缩放，不生成图片。

转向仍受现有三视图素材限制：中间角度是短交叉过渡，会短暂出现两个轮廓重叠，没有新增四分之三视角原画。此处没有把三视图伪称为完整3D旋转。

## 资源与启动

| 项目 | 本次实测 |
| --- | --- |
| 固定PNG | 48件，3,355,160字节，约3.20 MiB |
| 动作浮点采样 | 155,520字节，约152 KiB；已编入程序 |
| 部件RGBA纹理 | 10,629,428字节，约10.14 MiB；不含窗口、驱动等额外开销 |
| 最小运行包 | `build/MX002-skeletal-runtime.zip`，约3.70 MiB |

双击根目录`run.cmd`可构建和游玩。执行`package.ps1`可重新打包；解压后双击包内`build/MX002.exe`，保留`build`与`图片`的目录关系。运行包只含程序、48个PNG和使用说明，不需要旧逐帧素材、Python或编译器。

修改动作时先调整`tools/skeletal60/rig.py`，再运行`export_runtime.py`重建C数据头并构建游戏。该导出器只读现有PNG，在内存校准一次站姿标尺，不输出PNG。

## 验收证据

- `test.ps1`：原32项物理、3173项动画断言通过；新增骨骼69711项断言及绑定/混合检查、895项状态适配断言通过。
- `build.ps1`：C99、`-Wall -Wextra -Werror`构建通过。
- `tests/launcher_tests.ps1`：代码页936、临时工作目录、真实`run.cmd --verify`构建启动及95项GPU场景通过。
- `verify.ps1`：正式工程95个GPU场景通过；独立目录只复制程序与48件PNG，再完成95个场景；部件缺失和损坏都按预期退出并指出文件。
- `runtime_visual_check.py`：读取四向待机与八条转向中点的12张真实窗口截图，红色核心轮廓均为第392至599行，即208像素。此检查只覆盖这些截图的指定区域与颜色条件，不等于所有动作的美术验收。GPU报告的`standingReferenceHeight`仅是参考标尺，不用它冒充实际像素测量。
- 骨骼实现独立对照Python基准：17280个关节，姿势最大误差约4.04e-6、世界坐标约5.75e-5。
- 两轮独立复审发现并修复：极小负循环进度可越界；半蹲起冲错误套用深蹲导致约34像素跳变。增加回归检查后，同一半蹲探针跳变约0.62像素，复审关闭这两项问题，无剩余Critical/Important问题。

生成报告位于忽略提交的`verification/`：`skeletal-resource-report.json`、`skeletal-visual-report.json`及GPU场景报告/截图。没有将验证截图混入角色运行资源。
