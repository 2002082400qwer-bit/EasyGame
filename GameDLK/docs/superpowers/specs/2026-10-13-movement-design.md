# 横版动作原型设计

用户已指定 C + raylib、工程位置、角色资源及四种动作，本轮按该范围实现。

## 方案选择

推荐直接使用已有侧面 PNG 图集：保留原美术，使用 C 状态机控制动画。独立 PNG 也可用但加载文件更多；重新制作动画会扩大本轮范围。原图朝左，向右通过负源矩形宽度镜像。

## 结构

- `src/player.h`、`src/player.c`：无 raylib 依赖的移动、重力、落地、下蹲、冲刺控制与动画帧选择。
- `src/main.c`：窗口、键盘、资源定位、图集加载、测试场、动作状态显示和截图验证。
- `tests/player_tests.c`：验证左右移动、空中不能二段跳、落地、下蹲碰撞、冲刺距离/冷却/方向锁定、边界和不同更新频率。
- `build.ps1`、`run.cmd`、`test.ps1`：使用工程内便携 GCC 和 raylib 6.0；构建产物放 `build`。

## 动作规则

站立碰撞高 156、宽 48；下蹲高 98，脚底保持不动。走速 260 像素/秒，蹲行 95；跳跃初速 -680、重力 1800。冲刺速度 900、持续 0.18 秒、从开始计冷却 0.6 秒；按下触发，按住不连发，空中一次直至落地。下蹲时不能直接跳或冲刺。冲刺中方向锁定，垂直运动继续受重力影响。

物理状态优先决定动作：冲刺 > 空中 > 下蹲 > 落地缓冲 > 行走 > 待机。跳跃空中帧等待实际落地，落地后播放恢复帧。无物理依赖的动画查询可通过同一控制器测试。

## 资源与出错处理

只加载 `图片/游戏素材/diluc-game-sprites/diluc/atlases/256` 中的三张侧面图集。Windows 下先用宽字符文件 API 读取中文路径，再调用 raylib 内存解码接口，避免中文路径编码问题。程序从可执行文件路径寻找工程根目录；缺图报错退出，不静默用占位角色替代。

## 验证

先创建测试和接口空实现，观察行为断言失败，再补齐实现。实际 GPU 程序提供自动演示模式，通过同一控制器执行动作并生成截图、运行报告；截图逐张目视检查。文档注明临时待机和下蹲帧的局限。
